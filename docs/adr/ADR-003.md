# ADR-003 — Difficulty algorithm vs LWMA variant; custom RandomX salt vs Monero-compatible merge-mining

**Status:** ACCEPTED INTERIM BASELINE (Experimental-v1)  
**Identifier:** ADR-003  
**Date:** 2026-10-29  
**Author:** OwnChain protocol decision phase  
**Depends on:** none  
**Supersedes:** none  

---

## 1. Context

OwnChain v1 (`docs/protocol-v1.md`) uses:

- **Difficulty algorithm:** CryptoNote / Monero-style lagged retarget (§4.1): lookback window `max(0, h − 735)` through `h − 16` (15-block lag), trim to 600 samples, 120-second target, $\lceil \text{total\_work} \times 120 / \text{time\_span} \rceil$, fail-closed to difficulty 1. Implemented in `src/difficulty.rs` with checked U256 arithmetic and golden vectors in `docs/test-vectors-m1c-difficulty.json`.
- **Proof of work:** RandomX algorithm v1, reference implementation release `v1.2.3`, pinned commit `12f2c2ffe2108d6cf54c391fee33c8bc3646cdab`, using `configuration.h` defaults except `RANDOMX_ARGON_SALT`, which is the exact byte string `OwnChain-PoW-v1` (§3, §4 Consensus).

---

## 2. Decision: Interim Baseline

### 2.1 Difficulty algorithm: Retain Monero-style difficulty
- **Retain the Monero-style algorithm:** The implemented CryptoNote / Monero-style lagged retarget from `docs/protocol-v1.md` §4.1 is retained as the operative consensus algorithm for OwnChain experimental v1.
- **LWMA is NOT adopted:** An LWMA variant was considered, but the identified source (zawy12 `difficulty-algorithms` issue #3) publishes only an ambiguously-indexed $O(1)$ closed form without an authoritative loop specification or pinned test vectors. In accordance with task constraints, **no LWMA formula is invented and no LWMA numbers are executed**. Any future consideration of LWMA requires a pinned, authoritative upstream reference and validated test vectors.
- A reproducible simulation of the Monero-style algorithm under diverse hashrate scenarios is documented in `docs/experiments/`.

### 2.2 Proof of work salt: `OwnChain-PoW-v1` on devnet only
- The custom Argon2 salt `OwnChain-PoW-v1` differentiates OwnChain's RandomX instance from upstream defaults (`RandomX\x03`) and Monero, reducing cross-chain hashpower rental attacks per RandomX configuration guidance.
- **Merge-mining feasibility:** Matching salt alone is necessary but wholly insufficient for merge-mining; full block templates, key rotation schedules, and consensus rules must align.
- **Interim baseline:** The custom salt `OwnChain-PoW-v1` remains active on **devnet only**.

### 2.3 Production PoW configuration gate
- The final proof-of-work configuration (including production salt and merge-mining evaluation) is a **mandatory pre-public-testnet gate** (`protocol-v1.md` §12 Gate 4).
- Mainnet launch, exchange listing, and production PoW approval remain strictly out of scope.

---

## 3. Alternatives

| Alternative | Assessment |
|---|---|
| **A. Keep Monero-style difficulty (Accepted interim)** | Already implemented and tested (§4.1, `src/difficulty.rs`). Verified stable under tested hashrate conditions. |
| **B. Adopt LWMA variant (Rejected/Inconclusive)** | No authoritative loop formula or pinned test vectors exist; inventing formulas is forbidden. |
| **C. Keep custom salt `OwnChain-PoW-v1` devnet-only (Accepted interim)** | Protects devnet from hashpower rental attacks while deferring production PoW parameters to the pre-testnet gate. |
| **D. Switch to Monero-compatible salt now (Rejected)** | Salt change alone does not enable merge-mining and forfeits isolation protection. |

---

## 4. Consequences & Risks

**Positive:**
- Avoids adopting unverified difficulty algorithms without authoritative reference implementations.
- Maintains consistency with existing verified code in `src/difficulty.rs`.
- Devnet remains protected against generic RandomX hashpower rental attacks.

**Preserved Risks:**
- Monero-style difficulty exhibits adjustment lag under severe hashrate drops (e.g. 90% drops produce transient block-time spikes before catching down).
- Deferring production PoW decisions leaves long-term testnet/mainnet PoW parameters to be resolved at the pre-public-testnet gate.
- Same-environment determinism of simulations does not guarantee bit-identical cross-platform floating-point draws.

---

## 5. Decision Record

- **Status:** ACCEPTED INTERIM BASELINE for experimental v1.
- **Scope note:** Mainnet launch, production PoW approval, and exchange listing remain out of scope.
